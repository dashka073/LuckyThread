# Lucky Threads

Программа считала счастливые билеты (сумма первых трёх цифр равна сумме последних трёх) в три потока и при каждом запуске выводила разные результаты. Задача: найти причину и исправить программу так, чтобы результат был правильным, потоки работали параллельно и блокировали друг друга как можно меньше.

## В чём была проблема

В исходном коде все три потока работали с общими переменными x и count. Это гонка данных (race condition):

- x++ и count++ не атомарны: каждая операция состоит из чтения, увеличения и записи. Два потока могли прочитать одно и то же значение, и тогда один билет проверялся дважды или увеличение счётчика терялось.
- Между проверкой x < 999999 и x++ другой поток успевал увеличить x. Из-за этого x мог выйти за границу и проверялись числа вроде 1000000, которых быть не должно.
- Несколько потоков одновременно выводили числа через println, поэтому порядок вывода был случайным.

## Как исправлено

- Диапазон от 1 до 999999 делится на три равные части, и каждый поток проверяет только свою. Билеты не пересекаются и не дублируются.
- У каждого потока свой список найденных чисел. Общих изменяемых данных нет и потоки не ждут друг друга.
- Главный поток вызывает join() для каждого потока, и только потом читает его результаты. После join() все записи потока гарантированно видны главному потоку.
- Вывод делает только главный поток. Потоки идут по порядку диапазонов, поэтому числа выводятся по возрастанию и результат всегда одинаковый.
- Проверка билета вынесена в методы isLucky() и digitSum(), а число потоков и верхняя граница заданы константами.

## Результат

В конце программа всегда выводит Total: 55251, сколько бы раз её ни запускали.
